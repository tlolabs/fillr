# Native Chabot backgrounds on macOS

Open **Settings → Background** to inspect the Mac, benchmark it, and choose a performance profile. **Fastest build** is the default. **Balanced** chooses a configuration within 10% of the measured fastest rate with smaller bounded decoder/queue resources. **Keep Mac responsive** prefers hardware encoding and smaller decoder/queue resources; the tool does not claim to measure energy consumption or interactive responsiveness.

The quick scan records the CPU, logical CPU count, RAM, Metal devices, macOS/app versions, hardware codec capabilities, power mode, and thermal state. Capability detection is distinct from successful runtime use. Metal composition is required. Hardware decoding remains codec dependent: unsupported codecs use CPU decoding even when hardware decoding is preferred. Hardware and software encoder requests require confirmation of the active backend; unconfirmed or failed candidates cannot win a benchmark.

Quick benchmarks compare short samples of the candidate configurations. Thorough benchmarks use longer samples at beginning, middle, and end windows and rank complete configurations by median rate. Use the selected media folder for actual footage; when the complete Chabot project and intro are available, the exact project supplies cuts and panel sources. Otherwise the tool samples actual video files in the selected folder. Built-in interlaced MPEG-2 footage is used only when real footage is absent. Existing but invalid media produces an error rather than silently switching to test footage.

Sample timing includes native initialization, source decoding, Metal deinterlacing/scaling/composition, H.264 encoding, and MP4 finalization. MPEG-2 trims decode and discard preceding pictures to preserve sequence initialization, and that preroll cost is included. Preparation and complete decode verification are excluded and recorded separately. Sample rates estimate rendering performance; they are not measurements of a complete background build. Failed attempts and incomplete/cancelled reports remain visible in the report and are excluded from recommendations. **Show Report** opens the retained evidence.

Profile selection and manual overrides save immediately. Overrides take precedence over profile defaults. Hardware, OS, app, selected-source, and detected footage identity changes invalidate stored measurements. Unmeasured or stale recommendations are labeled and use scan-based defaults until new measurements are available. Profiles tune decoder selection/threads, bounded source queues, and encoder frames without changing output quality settings.

Choose **Build Background…** independently of **Build Folders**. Select the media root containing `Chabot News Backgrounds/Text Crawl.psd`, the Comp 1 intro, and the show date. A ready 14-folder collection is used directly, including ProRes LT media; after Build Folders its export journal restores the renamed paths. A saved `Footage.prproj` can also be selected explicitly. The importer supports the existing cut-only Premiere sequences, preserving their cuts and source trims; it rejects missing files, gaps, overlaps, retiming, custom effects, and unsupported edits. It is not an arbitrary After Effects or virtual-set importer. PSD cached pixels and native CoreText date artwork supply the two moving crawls. Native date antialiasing and GPU filtering can differ from Adobe rasterization.

With **Use all available footage** enabled, output lasts to the shortest news Comp, including lengths greater than ten minutes. Longer Comp timelines trim only their ending clips; the intro repeats to cover the same duration. Disabling the option retains 17,982 frames (599.9994 seconds). The native job limit is seven days with bounded frame counts and exact per-panel coverage. Output remains 1920×1080, 30000/1001 fps, progressive square pixels, limited-range Rec.709, H.264 High/4.2 at a 16 Mbps target, and no audio. A private sibling temporary movie is fully decoded and checked before the final filename appears. Existing files are never overwritten. Cancelled or failed jobs do not produce a final movie. Native job/report/artwork evidence is retained under the user's Application Support `FILLR/Background` directory.

## Build and validation

`script/build_background_ffmpeg_macos.sh` builds FFmpeg 9.0.2 from the same verified source archive and patch used by the collection probe. It builds universal arm64 and x86_64 static `avformat`, `avcodec`, `avutil`, and `swscale` libraries under `target/background-ffmpeg`. Programs, network support, automatic external-library detection, GPL, and nonfree components are disabled. The native ObjC++ engine calls the libraries, Metal, and VideoToolbox directly; it launches no runtime command-line renderer or artwork tool.

Both macOS build workflows compile these dependencies and include source/build/license materials. Ordinary local development uses `script/build_and_run.sh --build-only`; this is an ad-hoc-signed development build, not a notarized distributable. Standard distributables continue to use `script/release_macos.sh`, including Developer ID signing, Apple Accepted notarization, stapling, and Gatekeeper checks. Production updater checks remain unchanged.

Run `cargo build --release -p fillr-core`, `script/build_background_ffmpeg_macos.sh`, and `swift test --package-path native/macos`. Unit fixtures cover planning, PSD/artwork, profile policy, staleness, overrides, and cancellation. Native integration checks exercise bundled MPEG-2 fixture generation, probing, hardware rendering, and complete output decode. Hardware-only cases report explicit skips when their runtime services are unavailable.

The actual-project integration test is opt-in through `FILLR_BACKGROUND_TEST_MEDIA` and `FILLR_BACKGROUND_TEST_INTRO`. Set `FILLR_BACKGROUND_TEST_THOROUGH=1` for Thorough measurements and `FILLR_BACKGROUND_TEST_FULL_RENDER=1` for the full 17,982-frame render. `FILLR_BACKGROUND_TEST_OUTPUT` selects a parent directory for retained evidence. Proprietary footage is not required by ordinary tests or redistributed in the app. Windows and Linux background profiling/rendering are outside this implementation.
